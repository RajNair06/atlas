5 minutes · Go 1.22+ · one API key

Run atlas in five minutes

Clone the repo, drop in a free Gemini API key, and watch the gateway heal a failure you caused on purpose.

Before you start

  • Go 1.22 or newer — check with go version (download)
  • A Gemini API key — free at aistudio.google.com/app/apikey. It stays on your machine; it is never committed.
  • Anything POSIX-ish: Linux, macOS, or Windows via WSL.
No API key? The gateway still runs — when Gemini is unreachable, a built-in rule engine makes the healing decisions instead (every suggestion says which brain produced it). Everything below works either way.

1 · Clone and configure

# clone
git clone https://github.com/RajNair06/atlas.git
cd atlas

# put your API key in .env (this file is gitignored — never committed)
echo "GEMINI_API_KEY=your_key_here" > .env

# create your gateway config from the documented template
cp gateway.yaml.example gateway.yaml

2 · Start everything

make gateway

One command builds and starts five processes: the gateway on :8080 plus a three-service demo shop behind it (storefront :8081 → checkout :8082 → payment :8083). The demo shop exists so you have something to break.

Open the console: http://localhost:8080/ui

3 · Break something on purpose

In a second terminal, kill the payment service:

pkill -x payment

Now send a request that needs payment:

curl -v http://localhost:8080/buy

The curl hangs. That is not a bug — that is the product. The request failed, Gemini (or the rule engine) suggested a fix, and the gateway is holding the response until a human decides.

4 · Approve it in the console

Look at http://localhost:8080/ui. A pending card appeared the moment the suggestion was ready — pushed live over Server-Sent Events, no refresh needed. It shows the failed request, the suggested action, and the AI's written reasoning.

Bring payment back, then click Approve:

PAYMENT_PORT=8083 nohup bin/payment > /tmp/payment.log 2>&1 &

Your hanging curl completes: order placed in 61ms — with these response headers:

X-Healed: true
X-Healing-Action: retry
X-Healing-Attempts: 1

The client never saw the outage. The console's history feed shows a green healed pill — click the row for the full audit trail.

Prefer the darker ending? Click Reject instead: the curl immediately receives the original 502, and history records rejected with your verdict.

5 · Play with the switches

  • Approval gate toggle (header switch): flip it off and healing becomes fully automatic — outcomes still stream into history, marked auto-heal · approval gate off.
  • Chaos knob: restart payment with PAYMENT_DELAY=3s to simulate a slow (rather than dead) dependency.
  • Circuit breaker: keep payment dead and send several requests — after 3 consecutive failures the breaker trips and subsequent failures fast-fail in ~2ms with no LLM call. Wait out the reset window and it admits a single trial request.

Configuration reference

Everything lives in one YAML file. Environment variables are substituted with ${VAR} syntax.

KeyDefaultMeaning
server.port8080Gateway listen port
server.auto_healtrueMaster switch: attempt healing at all (restart to change)
server.require_approvalfalseInitial state of the human-approval gate — toggle live from the console
server.approval_timeout2mHow long a decision waits for a human before expiring
server.healing_budget5sHard cap on machine healing time per request (starts after approval)
server.breaker_threshold10Consecutive upstream failures that trip a circuit breaker (0 disables)
server.breaker_reset30sHow long an open breaker fast-fails before admitting one trial
llm.provider / modelgemini / gemini-3.5-flash-liteThe AI brain
llm.api_key${GEMINI_API_KEY}From environment only — never hardcode
llm.timeout2sPer-call LLM timeout
routes[].path / upstream—Exact-match route → upstream base URL
routes[].fallback""Backup base URL used by the fallback action and as a last resort after retries
routes[].timeout / retries—Upstream call timeout; max replay attempts
routes[].skip_healingfalsePass failures straight through (health checks, etc.)

Troubleshooting

  • Port already in use — lsof -i :8080 to find the squatter; scripts/stop-demo.sh clears atlas's own processes.
  • "API key not valid" — check .env exists and the gateway was started with it sourced (make gateway does this automatically).
  • Gemini 503 "high demand" — free-tier models spike. atlas degrades to its rule engine automatically; retry later for AI reasoning.
  • No pending card appears — the breaker may be open from earlier failures (fast-fails skip the LLM). Wait out breaker_reset, or restart the gateway to clear breaker state.
